# Shared mechanics

Helpers used by more than one frame. Roadmap §4 is the registry; the rule there is that **a helper
is born with its first consumer**, in its own sub-folder, with its own specs — and its interface is
frozen the moment that sub-project ships, recorded in roadmap §4 and in memory
`sixth-voice-build-state`. A later frame that needs more extends the helper in its own sub-project,
with every earlier spec still green.

The shape is usually the Draugr's: a static-function script plus whatever `.tres` it needs, no
autoload, no `class_name`. Every consumer reaches it by `preload`. **Armor is the one family that
isn't**: see its row below — two `Buff` subclasses (one `TO.STATBLOCK`, one `TO.RESIST_DAMAGE`)
parameterised by `@export`s on each consumer's own `.tres`, not a static-function script at all.

**Why no `class_name`**: global class names are registered from `project.godot`'s class list, which
is built at startup — so a `class_name` declared in a script a mod loads at runtime is never
registered, and cannot be referenced by that name at all. (This is a different problem from Godot
#83542, which is why a `class_name` script in the *base game* cannot be reliably script-extended;
that one is why the engine has so many autoloads. Both end at the same advice, for different
reasons.)

Built, and the interface frozen when its sub-project shipped — listed in the order they became
shared families, which is not the order of the frames: Armor's code was born at frame 2 and only
became a family at the Myconid.

|---|---|---|---|
| Overshield | 4 Myconid, SP1 | `current` `has` `grant` `increase` `grit` | Sluagh, Hazard, Naga, Primrose, Black Mountain |
| Armor | 2 Fitzgerald, SP4 (promoted at 4 Myconid, SP2; the Fitzgerald's own `.tres` re-pointed at the frame close) | `buff_armor_statblock.gd` `armor_amount` + `buff_armor_reduction.gd` `reduction_amount` `damage_types` `until` — always applied as a PAIR, with matching `until` | Reinforcement Blast, Fungal Network, Uffish Gyre |
| Teleport | 5 Maiden's Blush, SP1 (observe/intercept) + SP2 (perform) | **Thirteen, all frozen.** Observe/intercept: `is_teleport` `destination` `forcer` `movement_type` `is_own` `veto`, plus `OWN_TAG`. Perform: `candidate_tiles` `pathfinder` `pick_tile` `move` `move_along`, plus **the shove** (SP2, Sluagh): `forced_movement_type` `shove` — the "somebody else's shove" shape `is_own`'s docstring names, involuntary and **deliberately untagged**, for moving a unit that is NOT the caller. `shove` hangs the SHOVER's `SpecificAction` on the event, so `forcer()` returns them and a self-exemption written as `are_enemies(holder, forcer)` correctly does NOT fire. **The two move routes are not interchangeable** — `pathfinder` goes through `Pathfinder.create`, so Immobilized and every `MOVEMENT_RESTRICTION` ban apply (Abjuration wants that); `move` sends a hand-built single-step path and so builds no pathfinder at all, which is the only route that beats a ban (Step needs that). `move`/`move_along` run INLINE and hand the move core back, unlike Blinkspace which queues and returns. | Purple Thorn, Leoleth (ZIP), Sluagh (Hunt), Koremasa (Vanish), Six Sky |
| Efficient (core-power refund) | 5 Maiden's Blush, SP2 | `efficient.gd`: `mark_used` `is_marked` `refund` (returns whether it refunded, and is idempotent), plus `USED_KEY` / `UNUSED` / `USED`. A consumer carries TWO files on its core Kit: an `action_efficient_refund.tres` pointing at the shared reaction script (`combat_end` for a living mech, `unit_spawn` as the safety net) **and `passive_efficient_used.tres`**, the `PassiveDieCounter` with `resets_on_spawn = false`. **The passive is not optional**: `GearCore.short_repair` throws away every gear-state key except those of such passives (`gear_core.gd:144-150`) and every spawn runs it, so without it the spawn half is dead code. | Lovers Knot, Black Mountain |
| Terrain (difficult ground) | 6 Vauban, SP1 | **Four statics, all frozen:** `is_difficult(map, tile)` `is_unit_in_difficult(unit)` `is_entering_difficult(unit, next_anchor)` `lay(activation, specific, center, deployable)`, plus `PassiveGatedTerrainZone` with one `state_key` export. `lay` runs INLINE and hands the spawned unit back (the `Teleport.move` shape, not the Apocalypse Rail's queue-at-a-priority) — **or `null` when the spawn did not land** (a null or aborted spawn core, or a unit that never reached the map), so a caller must check the return before using it; `Unit.is_valid` is not that check, because it does not include `is_on_map`. **The unit it spawns is OWNED by `specific.unit`, and a deployable frame that must outlive its owner has to set `is_deactivated_on_owner_death = false` itself** — the export defaults to `true` and `EventService.remove_unit_from_game` kills owned markers that have it. **A consumer that wants "one field out at a time" must INTERSECT `deployed_ids` with the map**, the way `UnitAction.get_deployables_from` does (`unit_action.gd:537-545`) — never read the array for emptiness the way `action_jericho_deployable_cover.gd:5` does. `lay` records ownership before it spawns, so an aborted lay leaves the never-landed id behind; that residue is vanilla's own ordering (`action_system_deploy.gd:119` sets the owner, `:125` only then queues the spawn) and every vanilla deployable carries it. Not born: a lifetime for laid terrain, a Burst 2 frame, "damage in". | Leoleth, Shackleton |
| Lock-on consumed hook | 10 Naga, SP1 | **Five statics, all frozen when SP1 shipped (2026-09-22):** `was_consumed(context:Context) -> bool` (an `attack` context: `AttackRoll.check(object, &'consumed_lock')`; an `attack_declared` context: the target holds `buff_lock_consumed`), `consumer(context:Context) -> Unit` (`context.unit.get_attacker(context)` - an owned drone resolves to its owner), `is_lost(triggering:EventCore) -> bool` (a `statuses_changed` event whose `category_str` is LOCKON - the SAME virtual event carries the apply at PRE, so the caller reacts at POST), `apply(event, target:Unit, source_gear:GearCore) -> bool` (MANUAL, source = the gear's persistent id; false and no-op if already locked, if immune, or with an invalid gear), `source_of(unit:Unit) -> StringName` (the live status's source, empty if unlocked). **Recorded for the Black Mountain:** the consume clears with NO source (`action_consume_lock_on.gd:42`), so after a consume nobody can read whose lock it was - read `source_of` at ATTACK_DECLARED PRE, ahead of the consume reaction, and stash it. An ability clear (Stabilize) DOES carry the source. `spec/test_lockon.gd` pins all five signatures and fails on a sixth: an addition updates that pin in the sub-project that adds it. | Naga (the core passive, the core active, Ping, Binding Fangs), Black Mountain |

Nothing with a vanilla precedent belongs here: limited weapons that attack without charges follow
the Injector Drill, and `mt_guardian` / `mt_fragile` / `mt_slow` / `mt_exposed_reactor` are vanilla
trait Kits to be referenced, not reimplemented.
